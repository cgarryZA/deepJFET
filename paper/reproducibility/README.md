# Reproducibility package

This folder is the entry point for anyone trying to reproduce the
figures and numbers in the paper. Every artefact in `paper/data/`
(transistor count, register-level emulator diffs, timing analysis,
sensitivity sweep) is regenerated by a single Python invocation against
the repository at the same commit as the paper.

## Repository layout

```
deepJFET/
├── cpus/4004/                # LTspice .asc schematics + config.py
│   ├── alu.asc
│   ├── instruction_register.asc

│   ├── controls.asc
│   ├── pins.asc
│   ├── program_counter.asc
│   ├── step_counter.asc
│   ├── scratchpad/           # composable: Controls + Bus1/2 + Pair 1..8
│   ├── stack/                # composable: Controls + Bus + Level 1..3
│   ├── programs/             # 4004 assembly programs
│   │   ├── FloatingPoint/    # 16-bit FP multiplication
│   │   ├── Load5/            # smoke-test load-and-add
│   │   └── BitwiseAND/       # MCS-4 manual AND subroutine (Week 3)
│   └── config.py             # JFET model, supplies, gate R values, COMPONENTS list
├── lib/gates/                # primitive .asc gates (INV, NAND, NOR, 3-/4-input)
├── model/                    # JFET physics + RC timing model
├── simulator/                # event-driven gate-level Python simulator
├── tools/                    # analysis and build scripts (see below)
└── paper/                    # this manuscript
    ├── Main.tex
    ├── Appendices.tex
    ├── data/                 # auto-generated tables, CSVs, macros
    ├── supplementary/        # detail moved out of the main paper
    └── reproducibility/      # you are here
```

## One-command rebuild

From the repository root:

```
python paper/build.py
```

This (1) regenerates everything under `paper/data/` and (2) runs
`pdflatex` -> `biber` -> `pdflatex` -> `pdflatex` for both manuscript
variants. Prose macros (`\TotalJFETCount` etc.) and the
transistor-count table refresh automatically from the current state
of `cpus/4004/`, so changes to the schematics propagate into both
PDFs on the very next build.

### Manuscript variants

The manuscript ships in two variants compiled from a shared body:

- **`paper/Main.pdf`** — the master journal version, currently
  ~14 pages. Includes the full transistor-level subsystem schematics
  (ALU, instruction register, program counter, stack, scratch pad,
  pins, ROM), the verbose subsystem-by-subsystem architecture walk,
  the supplementary current-draw plots, and the FP register-value
  table.
- **`paper/jxcdc/Main_JXCDC.pdf`** — the compressed JXCDC variant,
  currently ~10 pages and targeting 4--8 once further figure cuts
  land. Replaces the verbose subsystem prose with a single compact
  paragraph plus the transistor-count table; keeps one logic-primitive
  figure, the top-level CPU block diagram, the storage primitive, the
  AND-routine register plot, one NAND figure at the operational
  frequency, and one NOR figure at the bandwidth limit.

Both variants share `paper/preamble.tex` and `paper/body.tex`. The
`\ifjxcdc` boolean is set false in `Main.tex` and true in
`Main_JXCDC.tex`; figures and prose paragraphs that differ between
variants are wrapped in `\ifjxcdc...\else...\fi` inside `body.tex`.
Edit `body.tex` once; both PDFs pick up the change on the next build.

Useful flags:

```
python paper/build.py                       # both variants (default)
python paper/build.py --variant master      # full version only
python paper/build.py --variant jxcdc       # JXCDC version only
python paper/build.py --skip-data           # pdflatex only, reuse paper/data/
python paper/build.py --clean               # wipe aux files (.aux .bbl ...) first
python paper/build.py --quiet               # less stdout
python paper/build.py --open                # open the PDF(s) when the build succeeds
```

To regenerate the data artefacts alone (no LaTeX run):

```
python paper/regen_data.py              # all steps
python paper/regen_data.py --list       # see available step keys
python paper/regen_data.py --only count # just the transistor count
```

## Reproducing each headline result

| Headline result | Command (run from repo root) |
|---|---|
| Regenerate Table II (transistor count per subsystem) | `python tools/count_transistors.py --cpu 4004` |
| Derive expected state for a new program | `python tools/derive_expected_state.py cpus/4004/programs/<name>/` |
| Assemble a 4004 program | `python cpus/4004/programs/Assembler.py` (writes `Machine.bin`, `Machine.hex`, ROM PWLs) |
| Build the flat CPU schematic with a program loaded | `python tools/build_cpu.py 4004 --program <name>` |
| Run register-level diff (FloatingPoint, paper-headline mode) | `python tools/trace_synced.py --program FloatingPoint --resync never` |
| Run register-level diff (BitwiseAND, paper-headline mode) | `python tools/trace_synced.py --program BitwiseAND --resync never` |
| Diagnostic mode (re-sync after each divergence) | append `--resync on-divergence` to either of the above |
| Generate frequency-sweep testbench (`.cir`) | `python tools/gen_freq_testbench.py` |
| Generate sensitivity-sweep testbenches | `python tools/gen_sensitivity_testbench.py` |
| Analyse LTspice `.log` (after running `.cir` in LTspice) | `python tools/analyze_ltspice_log.py --sweep {freq,sensitivity}` |
| Regenerate every paper data table in one shot | `python paper/regen_data.py` |
| Full rebuild (data + master + JXCDC PDFs) | `python paper/build.py` |
| Build the supplement bundle (`supplement.zip` + `MANIFEST.csv`) | `python tools/build_supplement.py` |

All trace-diff and corner-sweep steps require the relevant LTspice
transient simulation to have been run first; `regen_data.py` skips
them with a clear note until the prerequisite `.raw` or `.log` files
appear on disk.

## What each script does

| Script | Purpose | Outputs |
|---|---|---|
| `tools/count_transistors.py` | Counts `SYMBOL njf` / `SYMBOL res` per subsystem from `cpus/4004/config.py`. | `paper/data/transistor_count.{csv,tex}`, `transistor_count_macros.tex` |
| `tools/trace_synced.py` (W3) | Register-level diff between LTspice CPU and Python emulator. | `paper/data/trace_diff_{fp,and}.{csv,tex}` |
| `tools/freq_sweep.py` (W4) | Worst-case combinational chain delay, RC-derived f_max. | `paper/data/timing_chain.csv`, `freq_max.tex` |
| `tools/sensitivity_sweep.py` (W4) | Noise-margin sweep over R1/R2/R3 and supply voltage. | `paper/data/sensitivity.{csv,tex}` |

## Reproducing the LTspice simulations

The Python emulator and analysis scripts above do not require LTspice
itself. Re-running the LTspice transient simulations (e.g. to regenerate
`cpus/4004/4004.raw`) does -- install LTspice and:

```
python tools/build_cpu.py 4004 --program FloatingPoint   # assemble flat .asc
# Open cpus/4004/4004.asc in LTspice and run the transient analysis,
# or invoke the LTspice CLI directly if available on your platform.
python tools/trace_synced.py --raw cpus/4004/4004.raw --program FloatingPoint
```

The expected output state for each program lives in
`cpus/4004/programs/<name>/README` (or `expected_state.yaml` from
Week 3 onwards).

## Dependencies

### SiC JFET model parameters: provenance and redistribution

The SPICE NJF parameter card in `cpus/4004/config.py` (`beta`, `vto`,
`lmbda`, `is_`, `n`, `isr`, `nr`, `alpha`, `vk`, `rd`, `rs`,
`betatce`, `vtotc`, `xti`, `eg` plus the junction capacitances) was
supplied by the project supervisor and appears in the publicly
released MEng report from which this work descends. It is shipped in
this package on that basis -- the values are not novel here -- but the
underlying device model belongs to its original owner. Anyone wishing
to *redistribute* the parameter values beyond this academic
reproducibility package (for example, vendoring them into a separate
SiC JFET tool, an integrated SPICE library, or a derivative
publication that is not citing this work) should obtain permission
from the original model owner. Anyone wishing to *reproduce* the
LTspice transient simulations on a different SiC JFET technology
should replace the parameter card with a compatible model card for
their own devices.

### What this package does NOT include

The package excludes machine-specific LTspice transient output
(`.raw`, `.log`, `.net`, `Machine.bin`, `Machine.hex`). These are
regenerated locally by running the workflow above.

## Data freshness

Every file under `paper/data/` carries a `% Auto-generated` header.
Do not hand-edit them -- changes will be silently overwritten on the
next regen. If a generator produces something the paper needs and the
output format is wrong, edit the generator under `tools/`.

## Shipping the supplement

When the paper is ready for upload, the reproducibility bundle is built
with a single command:

```
python tools/build_supplement.py
```

This writes two files into this directory:

- `MANIFEST.csv` -- one row per shipped file, with size, SHA-256, and
  the generator script that produces it (or `static` if hand-edited).
  Use this to verify integrity after download.
- `supplement.zip` -- the same file set bundled for upload to Zenodo or
  similar. Contains the manuscript sources, all `tools/*.py`, the LTspice
  `.asc` schematics, the test programs, the corner-sweep `.cir`
  test benches, the gate library, the device model, and the
  auto-generated `paper/data/*.csv` and `*.tex` tables. Explicitly
  EXCLUDES machine-specific LTspice output (`.raw`, `.log`, `.net`,
  `Machine.bin`, `Machine.hex`) -- those are regenerated locally by the
  recipient.

### Zenodo + DOI mint

`paper/.zenodo.json` holds the upload metadata template. Before
uploading:

1. Set the `license` field to a Zenodo-recognised SPDX identifier
   (e.g. `MIT`, `apache-2.0`, `cc-by-4.0`).
2. Add affiliation ORCID IDs to each `creators` entry if available.
3. Upload `supplement.zip` and the populated `.zenodo.json` via the
   Zenodo web UI.
4. After the DOI is minted, paste it into `paper/CITATION.cff` (uncomment
   the `identifiers:` block at the bottom) and into the
   reproducibility statement in `paper/Main.tex` Section V.

### Freezing the repo state

The commit that corresponds to the uploaded supplement should be tagged
for reference:

```
git tag -a paper-arxiv-v1 -m "Manuscript v1 submission state"
git push origin paper-arxiv-v1
```

Do not force-push after tagging.
